# AIエージェント基盤 — 設計判断の記録

最終更新: 2026-09-08 / rev.3

## 確定した前提

- 用途: 社内業務の自動化（製品化しない・社内利用のみ）
- **AWS = 提供先（本番）** — cetacea.jp のコンテンツ・Webサービス。現在は MacBook から直接デプロイ
- **自宅の Mac mini M6 / 32GB = 開発ホスト ＋ 業務機 ＋ 常駐エージェント**（3役兼務・常時稼働）
- 開発対象スタック: WordPress、Next.js系SSG/SPA、Python APIサーバ、コンテンツ制作
- デプロイ: 段階的に CI（GitHub Actions等）へ移行
- ローカルLLM: 常駐させずオンデマンド起動
- 扱うデータ: 顧客情報・未公開財務を含む

## 決定的な制約

Mac mini M6 はユニファイドメモリ **最大32GB**、メモリ帯域 **153〜170GB/s**。
（64GB / 307GB/s は Mac mini の M5 Pro 構成のみ）

常駐13GB（macOS 6 / データ層 2.5 / エージェント層 3.5 / 検出パイプライン 1.0）＋ 残り19GB をモードで奪い合う。

- 開発モード: Node・ビルド 6 / Docker 5 / エディタ・ブラウザ 4 / 予備 4
- 業務モード: ローカルLLM 5 / KVキャッシュ 4 / 埋め込み 1.5 / バッチ作業域 3.5 / 予備 5

## 主要な設計判断

1. **モデル面とツール面を分離する** — MCPはツール/データ接続の標準であってモデル選択ではない。モデル切替は LiteLLM、ツール権限は MCP 側。
2. **3ゾーンに分ける** — ゾーン1=本番AWS（Mac miniからは読み取りのみ）／ゾーン2=開発（成果物はgit pushまで）／ゾーン3=業務（区分Aのデータ保持、本番にもGitにも触れない）。
3. **本番の書き込み権限は Mac mini に置かない** — CI だけが本番資格情報を持つ。移行前でも AWSプロファイルを読取専用／デプロイ用に分け、エージェントの環境変数にデプロイ用を置かない。これは最優先の一手。
4. **ローカル8Bは常駐させずオンデマンド** — 開発中のビルドにメモリを回すため。
5. **マスキングの主力をルール＋CPU NER（GiNZA等）に移した** — 常駐1GBで済み、8Bがロードされていなくても送出ゲートが常に機能する（rev.2からの変更点）。
6. **送出ゲートは開発・業務の両ゾーン共通の唯一の出口** — 区分A（ローカル固定、外部モデルを仮想キーに紐付けない）／区分B（マスク→外部→復元）／区分C（そのまま外部）。マスキングは100%ではないため区分Aは経路を断つ。
7. **開発と業務を1台の中で権限分離** — ファイル（暗号化ボリューム＋MCPのルート固定）、DB（業務/開発でDBとロールを分離）、MCP（別プロセス・別資格情報）、LiteLLM仮想キー3本、AWSプロファイル、Phoenixトレースの保存先。
8. **開発エージェントはローカルモデルを使わない** — コード生成は8Bとの品質差が最大。節約するとレビュー工数で損をする。
9. **MacBook は端末、Mac mini が作業実体** — Tailscale経由。MacBookを閉じてもビルドとエージェントが動き続ける。リポジトリの正はGit。
10. **推論エンジンは MLX / llama.cpp** — vLLM は実質NVIDIA前提でApple Siliconでは不可。
11. **商用APIは Amazon Bedrock を本命に** — 既存AWS請求に合流、IAM/CloudTrailで制御と監査。直販1本を比較・保険として保持。

## コスト（1人利用）

- 初期: ¥185,000〜255,000（Mac mini + 外付けSSD + UPS）— GPUサーバ案の約1/20
- 月額計: ¥31,000〜90,000
  - 商用API・開発: ¥20,000〜60,000（**最大の変動費**。プロンプトキャッシュのヒット率で倍近く変わる）
  - 商用API・業務: ¥10,000〜20,000（区分Aはローカルなので課金されない）
  - 電気代 ¥1,000〜2,000 / CI ¥0〜5,000 / Tailscale・回線 ¥0〜3,000

## 却下した案

- **オンプレGPUサーバ（RTX PRO 6000 × 2、初期¥3.6〜4.8M）** — 30人規模の試算でも商用APIのほうが安く、この規模ではコスト削減の理由にならない。
- **Dify / Keycloak / Langfuse自己ホスト / Temporal / Docker Desktop** — 32GBに載らない。可観測性は Phoenix、認証は Tailscale、プロセス管理は launchd で代替。
- **Langfuse Cloud** — プロンプトと応答が外に出るため機密要件と矛盾する。
- **macOSの別ユーザーアカウントによるゾーン分離** — 分離としては最も強いが常駐が二重になり32GBでは非現実的。権限による折衷案を採用。
- **OpenRouter等のアグリゲータ** — データ取扱いが背後の各プロバイダ依存で経路の説明がつかない。

## 未決事項

- 顧客との契約にデータ保管場所・再委託の条項があるか（自宅設置で最初に潰すべき論点）
- 区分Aの具体的な定義（実際の書類を見ながら決める）
- 最初に自動化する業務の選定
- 本番AWSの構成をコード化（Terraform等）するか — CI移行のついでに検討する価値あり
- Mac mini の購入有無 — 開発ホストを兼ねる以上、M5 Pro / 64GB の検討価値は rev.2 時点より上がっている
